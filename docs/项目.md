项目：TaskPilot（分布式任务调度平台） 定位：调度中心 + 执行器两段式，支持 cron/固定频率、分片、失败转移、重试、幂等、执行日志和告警。不是又一个 CRUD，核心难点是“集群里同一任务只触发一次、失败能转移、重复执行不重复生效”。

架构（3 个模块，够用）：

- scheduler-center：任务 CRUD、cron 解析、时间轮触发、领导选举、失败检测、分片调度、执行历史、告警；MySQL + Redis。
- executor：注册/心跳、任务处理器注册、分片参数、执行与结果上报、优雅下线；可水平扩展。
- common：DTO、枚举、异常、工具。
- 技术栈：Java 17 + Spring Boot 3.2 + Spring Cloud Alibaba（Nacos 注册/配置、OpenFeign 调用）+ MyBatis-Plus + MySQL 8 + Redis/Redisson + RocketMQ/RabbitMQ + Docker Compose + JMeter + GitHub Actions。
- 核心机制：
  - 触发：时间轮 + cron + DB 持久化 + 重启补偿；不要只靠每秒扫表。
  - 领导选举：Redisson 锁 + fencing token，保证多实例只有一个调度者；面试重点讲脑裂和重复触发怎么防。
  - 分片：shardIndex/shardTotal，平均/哈希/广播；执行器上下线时重新分配。
  - 失败转移：心跳超时 → 标记下线 → 分片重分配 → 重试/退避 → 死信/告警。
  - 幂等：executionKey（taskId + 触发时间 + 分片号）唯一索引 + Redis SETNX；至少一次语义，业务侧幂等。
  - 可观测：执行日志、耗时、成功率、告警 webhook；Actuator/Micrometer。
- 交付物：GitHub 仓库（README、架构图、接口文档）、设计说明（选主/fencing、时间轮、分片、失败转移、幂等、重试）、JMeter 压测报告（触发延迟/吞吐/故障转移时间）、2-3 分钟演示录屏。

5 周计划（每周 40 小时，留 1 周 buffer）：

1. 第 1 周：Maven 多模块 + MySQL 表（task/execution_log/executor_registry）+ 任务 CRUD + cron 解析 + 执行器注册/心跳 + 手动触发（OpenFeign）+ Docker Compose（MySQL/Redis/Nacos）。产出：手动触发端到端跑通。
2. 第 2 周：时间轮 + 定时触发 + 领导选举（Redisson + fencing）+ DB 持久化/重启补偿 + 执行日志；用 2 个 scheduler 实例验证同一任务只触发一次。产出：定时任务 + 集群不重复。
3. 第 3 周：分片 + 执行器上下线 + 失败转移 + 重试/退避 + 超时 + 幂等 + 死信。产出：杀掉一个执行器，分片自动重分配；重复触发不重复生效。
4. 第 4 周：管理端历史/执行器列表 + MQ 结果/告警 + MySQL 索引/慢查询优化 + Actuator/Micrometer + JMeter 压测 + GitHub Actions。产出：压测报告 + 部署文档。
5. 第 5 周：README/接口文档/演示录屏 + 简历 bullets + 模拟面试 2 次 + 修 bug；可选加分：用你的 LLM API 对失败日志做摘要/告警，但只作为附加模块，不挤占调度核心。

- 关键：所有数字用 JMeter 实测，不要编；例如“2 个调度实例、5 个执行器、1000 个任务，触发 P99 延迟 X ms，故障转移 Y 秒内完成”。

简历和 AI 辅助边界：

- 项目名可以写“TaskPilot（分布式任务调度平台）｜Java 后端｜AI 辅助开发｜2026/10-至今”。
- 角色按真实情况写：你定需求/架构、AI 生成代码、你验收和调试，就写“负责需求定义、架构设计与验收，AI 辅助编码”；不要写“独立手写/独立实现”。
- 这个项目的面试追问会很硬：为什么用时间轮不用纯扫表？Redisson 锁过期/脑裂怎么办？fencing token 怎么防重复？分片怎么重平衡？失败转移怎么保证不丢？幂等键怎么设计？你必须能画出架构图并解释取舍，否则项目会变成减分项。
- 建议你至少亲手写/改四个核心点：领导选举 + fencing、时间轮、分片/失败转移、幂等落库；其余用 AI 生成后逐行读懂。
- 简历 bullets 只写已完成的功能和实测数字；第 2 周有集群不重复的 demo 就可以写成“进行中”，不要等第 5 周。

范围控制（很重要）：

- 不要做：Kubernetes、Service Mesh、完整前端、十几个服务、复杂工作流 DAG；先把“调度中心 + 执行器 + 分片 + 失败转移 + 幂等”这一条主线做透。

- 不要同时做 AI 网关；一个项目做深，比两个半成品强。

- 不要只做单机定时任务；那和 Spring @Scheduled 没区别，体现不出分布式能力。

  按“调度中心 + 执行器”的两段式做
  管理端要 REST 为主 + 一个极简页面用于演示，不花时间做前端。
